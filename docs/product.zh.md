# 产品设计

[English](product.md) | 中文

## 问题

用户可以看到 DSH 部署暴露了哪些工具，但工具列表无法解释插件身份的运行时成本、外部状态活动或证据质量。单一风险分数会掩盖部署声明与运行时观察之间的差异。

## 产品目标

Runtime Nutrition Label 为每个已配置的插件或工具命名空间提供紧凑、机器可读且人类可读的报告。报告回答四个问题：

- 部署声明该插件可能执行什么操作？
- 哪些工具可见，它们的 schema 有多大？
- 当前进程窗口观察到了哪些调用、文件和网络主机名？
- 哪些字段是观察事实、配置推断或声明？

发布包是一个 DSH bundle。执行 `dsh plugin --profile <name> add dsh-runtime-nutrition-label` 会将 bundle 加入该 profile，并挂载采集器服务和人工命令，无需另外传入 patch。

## 用户

- 在启用插件前检查 profile 的 harness 操作员。
- 检查工具命名空间是否符合文档的插件作者。
- 调查异常工具或文件系统活动的安全与支持工程师。
- 在不保留秘密值的前提下验证有界运行时报告的 CI 与发布自动化。

## 标签语义

每个标签都有稳定的配置 id、显示名称、声明部分、观察部分和有界证据记录。工具归属来自精确名称和前缀。该插件不会声称可以从通用事件 payload 发现 Cordis fiber 归属。

产品不会生成单一总分。消费者可以对显式字段应用自己的策略，同时保留每个字段的来源和限制。

## 隐私与保留

默认报告保留大小、计数、耗时统计、主机名和可选路径样本。不会保留原始参数、原始结果、文件内容、凭据值、URL 路径、URL 查询串、URL 片段或 token。证据和代表性样本都有可配置上限。

## 非目标

- 替代 DSH 权限或 sandbox 策略。
- 证明没有发出 DSH 事件的隐藏提供方行为。
- 持久化长期审计归档。
- 使用通用信任或安全总分给插件排名。
- 在首个版本要求完整 Web UI。

## 成功标准

首个版本在以下条件下成功：`dsh plugin` 可以安装并激活 bundle，部署可以运行普通工具并查看一个有界 snapshot，而且无需读取原始模型或工具 payload 就能解释每个报告字段。其他渲染器或 telemetry exporter 可以消费同一个 snapshot，而不改变采集语义。
